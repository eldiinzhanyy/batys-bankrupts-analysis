# Анализ экономических рисков Западно-Казахстанской области (ЗКО)

Аналитический проект полного цикла: сбор данных из открытых 
государственных источников, очистка, анализ на SQL и визуализация. 
Тема — мониторинг экономических рисков региона (банкротства компаний 
и рынок труда).

## Стек
Python (pandas, matplotlib), SQL (SQLite), Power BI, Google Colab, Git

## Что сделано
- Собрал и очистил два датасета из сырых госвыгрузок (Excel с битой 
  структурой): список банкротов КГД и статистику безработицы по районам
- Feature engineering, обработка пропусков, дедупликация, приведение типов
- Анализ на SQL (агрегации, группировки, фильтрация групп)
- Интерактивный дашборд в Power BI
- Визуализации в matplotlib

## Ключевые находки
1. Один руководитель нередко связан сразу с несколькими компаниями-банкротами 
(в топе — до 8 компаний на одно лицо). Это сигнал, требующий проверки: 
возможны номинальные директора или преднамеренные банкротства.
2. Среди банкротов преобладают ТОО — 41 из 56 компаний.
3. Качество госданных низкое: дата решения суда указана лишь у 23 из 56 записей (41%), 
встречались дубли и пустые БИН. Поэтому анализ динамики по годам носит 
иллюстративный характер.
4. Уровень безработицы по районам ЗКО довольно ровный — от 4,4% до 5,7%, 
резких выбросов нет. Выше всего в Жанибекском и Каратобинском районах, 
ниже всего в Бурлинском.

## Чему научился 
- Работа с грязными данными: столкнулся с реальными проблемами госвыгрузок — съехавшие шапки, дубли, несовпадение локалей (точка, запятая), автоопределение типов. Научился диагностировать и чинить каждую.
- Приватность: убрал ИИН физлиц и обезличил ФИО перед публикацией — данные должны быть безопасны.
- Честность про ограничения: часть данных неполная (даты решений у 41% записей), поэтому выводы про динамику подаю как разведочные, а не доказательные.
- Границы данных: попытался связать банкроты с безработицей по районам, но в данных не оказалось нужного разреза — важнее признать ограничение, чем натягивать анализ.
- Работа с Git: вел проект в репозитории, следил, чтобы перед публикацией в открытый доступ не попадали персональные данные


## Структура репозитория
- `bankrupts_analysis.ipynb` — очистка и анализ банкротов (Python/pandas)
- `sqlnalog.ipynb` — SQL-анализ (SQLite)
- `bezrabotica.ipynb` — очистка статданных по безработице (многоуровневая шапка, приведение типов)
- `unemployment_zko_clean.csv` — очищенные данные по безработице
- `bankrupts_zko_clean.csv` — очищенные данные по банкротам
- `powerbi_dashboard.png` — дашборд Power BI
